## Goal
What the desktop first-run screen and the mobile app need before sign-in (`GET /api/v1/instance`)
and the signed-in account (`GET/PATCH /api/v1/me`, avatar upload / removal).

## Approach
- `GET /api/v1/instance` — public, `Cache-Control: public, max-age=300`, throttled by the group.
  Name (InstanceSettings), base URL, `AppVersion::current()`, `api_version: "1"`, sign-in methods
  (password + Google / GitHub / Microsoft — the Login page's rule, moved into
  `App\Support\Auth\SignInMethods` and used by the Login page, the homepage and the API), sign-up
  open, email verification required, `min_versions`, `authorize_path`. Nothing secret.
- `GET /api/v1/me` — `MeResource`: id, name, email, verification, avatar URL, bio, phone, time zone
  (stored + effective), daily digest, instance admin, created_at, workspaces (slug, name, role,
  owner, logo, plan limits + billing URL from the `Entitlements` contract), limits enforced, current
  device. There is **no** language / locale or theme column on users (theme is per browser,
  `localStorage`), so neither is exposed or editable.
- `PATCH /api/v1/me` — the fields the web Profile page edits: name, bio, phone (rules shared with
  `ProfileUpdateRequest`), timezone + task_digest (the `profile.preferences` rules, shared too).
  `email` → 422: changing it needs re-verification, web only.
- `POST /api/v1/me/avatar` (multipart `avatar`) / `DELETE /api/v1/me/avatar` — the web upload code
  moved into `App\Support\Profile\Avatar` (name from the detected MIME type, never the client's),
  used by `ProfileController::update` and the API.
- Controllers `App\Http\Controllers\AppApi\{Instance,Me,MeAvatar}Controller`, Form Requests in
  `App\Http\Requests\AppApi`, Resources in `App\Http\Resources\AppApi` (wrapped in `data`).
